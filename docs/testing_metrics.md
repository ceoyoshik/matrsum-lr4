## 3. Плотность дефектов

```
плотность = число дефектов / (строк кода / 1000)
          = 4 / (568 / 1000) = 7,04 дефекта на 1000 строк
```

По исполняемым операторам: `4 / 308 × 1000 = 13,0` дефекта на 1000
операторов. Для учебного проекта с завершённой интеграцией это ожидаемый
уровень: дефекты сосредоточены в проверках входных данных на границах
(целые произвольной разрядности, рваные матрицы, недоверенный ответ
модуля).

## 4. Среднее время нахождения дефекта

Отсчёт — от запуска первого варианта набора тестов до появления падения
с понятной причиной.

| Дефект | Время, мин | Обнаруживший тест |
| --- | --- | --- |
| BUG-3 | 8 | тест `is_number` на огромном целом |
| BUG-2 | 12 | тест рваной матрицы |
| BUG-1 | 18 | тест ответа с недопустимыми номерами |
| BUG-4 | 22 | тест записи несериализуемых данных |

```
среднее время = (8 + 12 + 18 + 22) / 4 = 15 мин
```

Все четыре дефекта найдены на этапе модульного тестирования, до запуска
CI и до ручной проверки. Дефектов, найденных на этапе интеграционного
тестирования, не было — это подтверждает, что границы модулей уже были
проверены в ЛР №3.

## 7. Выводы

1. Покрытие 100 % достигнуто без «пустых» тестов: каждый тест проверяет
   наблюдаемое поведение, а не строку кода.
2. Плотность 7 дефектов на 1000 строк при 100 % покрытии показывает, что
   покрытие не заменяет анализ границ: все дефекты находились именно на
   граничных и «недоверенных» данных.
3. Среднее время нахождения дефекта (15 мин) мало́ потому, что тесты
   писались одновременно с анализом кода методами «белого ящика».
4. Регрессионный набор стабилен: после четырёх исправлений ни один
   эталонный результат не изменился.
