# План и результаты тестирования (ЛР №4)

Документ описывает тестирование сквозного проекта **«МатрСум-11»**,
разработанного в ЛР №1–ЛР №3 и интегрированного в ЛР №3.

## 1. Объект тестирования

| Модуль | Файл | Строк | Назначение |
| --- | --- | --- | --- |
| Модуль ввода | `src/input_module.py` | 58 | чтение и проверка матрицы n × m |
| Модуль обработки | `src/processing_module.py` | 78 | поиск столбцов с нулём и их сумма |
| Модуль вывода | `src/output_module.py` | 27 | форматирование результата |
| Протокол обмена | `src/protocol.py` | 203 | JSON-сообщения, версии, файлы |
| Сопоставление данных | `src/mapping.py` | 50 | преобразование структур между модулями |
| Исключения | `src/errors.py` | 25 | типы ошибок интеграции |
| Точка входа | `src/matrsum.py` | 121 | запуск модуля обработки, повторы, тайм-аут |

Предметная область и вариант: **система обработки матриц** (сквозной проект,
вариант 11 по журналу). Метод из варианта 1 — эквивалентное разбиение и
анализ граничных значений; для уровня 3 дополнительно применены методы
«белого ящика».

## 2. План тестирования

| Параметр | Значение |
| --- | --- |
| Уровни тестирования | модульное, интеграционное, системное, регрессионное |
| Подходы | «чёрный ящик» (эквивалентное разбиение, граничные значения), «белый ящик» (покрытие решений, условий, комбинаторное) |
| Инструмент | pytest 9.2 + pytest-cov + coverage 7.x |
| Целевое покрытие | не менее 75 % (по заданию), фактическое — 100 % |
| Критерий входа | код ЛР №3 закоммичен, зависимости установлены |
| Критерий выхода | все тесты зелёные, покрытие ≥ 75 %, flake8 без замечаний, CI зелёный |
| Окружение | Python 3.14 локально, Python 3.11 и 3.12 в CI (Ubuntu) |

Запуск:

```
python -m pip install -r requirements.txt
pytest -q --cov=src --cov-report=term-missing
flake8 src tests
```

## 8. Регрессионное тестирование

Файл `tests/regression/test_regression.py` (16 тестов, маркер

(3 × 4, сумма `23.000`), стабильность формата JSON-конверта и текста

обмена. Регрессионный набор запускается отдельной задачей CI при каждом
push и pull request, а также еженедельно по расписанию.
