| № | Замечание | Решение |
| --- | --- | --- |
| 1 | `parse_response` не проверял диапазон и уникальность номеров столбцов (BUG-1) | добавлены проверки `1..MAX_DIM` и уникальности |

| 5 | Проверки размеров дублировались в модуле ввода и протоколе | оставлены в обоих слоях осознанно: ввод — для консоли, протокол — для доверенной границы |

## 5. Ревью тестов

Ревью проводилось по чек-листу (самостоятельное ревью, второй проход по
готовому набору).

| Пункт чек-листа | Результат |
| --- | --- |
| Имя теста описывает проверяемое поведение | да (`test_parse_size_rejects_invalid_values`) |
| Один тест — одна причина падения | да, кроме параметризованных наборов одного класса |
| Нет проверки реализации вместо поведения | да, тесты обращаются к публичным функциям |
| Нет «пустых» утверждений (`assert True`, проверка только длины) | да |
| Есть тесты на каждую ветку обработки ошибок | да, покрытие 100 % |
| Нет зависимости от текущего времени и сети | да |
| Тесты быстрые | да, весь набор — 2,3 с |

Найдено и исправлено в ходе ревью:

1. В тесте покрытия решений `parse_row` утверждение было записано через
   `assert ... or ...`, что скрывает часть результата — заменено на
   параметризацию с ожидаемым значением.
2. Тест `parse_response` собирал сообщение через `build_response(1, ...)`,
   что само по себе падало с `TypeError`; сообщение теперь собирается
   корректно, а проверяется именно разбор.
3. В ожиданиях нескольких тестов сумма столбца была указана неверно
   (суммировался не тот столбец) — исправлено по эталонному расчёту.
4. Четыре строки длиннее 79 символов и один неиспользуемый импорт —
   исправлено (`flake8` — 0 замечаний).
